Enterprise ordering / 2026

Rebuilding around the business rules

An ordering platform connected customer purchases to fulfillment and accounting in SAP. Replacing it meant untangling regional pricing, purchasing constraints, and delivery schedules without losing the rules that kept it running.

I developed the architecture and phased delivery plans, built customer and admin APIs and interfaces, and created parallel AWS infrastructure for the migration.

  • Normalized pricing into the units customers buy, preserving historical order data.
  • Built an order-event log and processing locks while keeping legacy status fields compatible.
  • Aligned interfaces with OpenAPI contracts, generated types, and automated checks.
More about the migration

I traced existing workflows and turned them into reviewable features, revising the plan as implementation revealed hidden dependencies. Shared user records preserved relationships and employee roles, with separate customer and administrator access boundaries.

The infrastructure work moved toward a consolidated Phoenix application on ECS, with GitHub Actions for delivery. New interfaces, APIs, infrastructure, and parts of the processing workflow were implemented by September. Queue handover, processing ownership, rollback observation, and the wider cutover remained part of the ongoing migration.

Insurance & payments / 2026

Modernizing one reliable step at a time

Quotes, payments, signatures, and policy creation had to stay coordinated while a Rails application was being replaced—even when events arrived out of order or processing stopped halfway through.

I extracted payment integrations into TypeScript services and built React checkout flows, using feature flags and Rails API clients to support incremental rollout.

  • Built durable webhook storage, duplicate-event protection, and recovery paths.
  • Bridged existing credentials into new authentication without password resets.
  • Preserved Rails audit history and added deployment checks that detect ECS rollbacks.
More about the migration

I separated payment collection from order finalization. Verified webhook signatures, PostgreSQL event storage, transactional worker claims, advisory locks, and completion checks protected processing. Retry and administrative recovery paths addressed interrupted work.

Tracing quote-to-policy behavior exposed separate checkout implementations and changed the delivery sequence. I consolidated shared work and documented the evolving design. By September, payment services, checkout flows, authentication and API foundations, audit compatibility, and deployment infrastructure were implemented; the broader Rails replacement remained underway.

Approach & tools

How I build

Start with the business rules. Use domain-driven design to give them clear names and boundaries. Organize features with Vertical Slice Architecture so related behavior stays together.

Keep the Unix philosophy close: small pieces with clear responsibilities. Make changes incremental, test the important behavior, and plan for what happens when something fails.

Exploring

Go

Go’s simplicity, static typing, and performance make it a language I’m excited to work with. I spent substantial time exploring it and evaluating it for agency projects. Its small surface area and straightforward tooling fit the way I like to build software.

For our agency’s needs at the time, the team’s familiarity with TypeScript and the libraries and integrations we already relied on made our existing stack the more practical choice. Datastar & hypermedia

Years of maintaining legacy applications have made me acutely aware of the cost of dependency churn, especially in the React ecosystem. React is still my go-to for most projects because it gives me the capabilities to build the interfaces clients need. But I’m increasingly interested in how much I can do with fewer dependencies.

I keep coming back to the idea of a “100-year web app”: software built on durable web foundations, with less to replace just to keep it running. This site is a small expression of that idea. Just HTML, CSS, and a few good fonts.

Datastar and hypermedia appeal to me as a way to bring that same restraint to richer, interactive applications. I want to explore how far I can take an interface with HTML, server-driven updates, and one small frontend dependency. I haven’t used Datastar in production yet, but I’m excited to do more with less.
